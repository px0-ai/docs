px0's commands read as **entity, then verb**: `px0 workflows new`, `px0 knowledge search`, `px0 guidelines review`. Once you know the entities, you can usually guess the command.

The only flat commands are the four that act on the install rather than on anything in your store: `init`, `doctor`, `version`, `update`.

Add `--help` to any command for its own flags. `px0 config get --help` and `px0 config set --help` additionally list every settable key.

## Global flags

| Flag | Effect |
| :--- | :--- |
| `--json` | Machine-readable output where supported. Implies no colour. |
| `--no-color` | Plain output, no colour or animation. Same as `NO_COLOR=1`. |

Both work at the root (`px0 --json runs list`), and the subcommands that support `--json` accept it in place too.

## Exit codes

| Code | Meaning |
| :--- | :--- |
| `0` | Success |
| `1` | User error — bad arguments, no such workflow, no store, a failed run |
| `2` | Connector error — an app is unauthorized or unreachable |
| `3` | Model error — the harness failed, timed out, or refused |
| `4` | Integrity error — a `px0 doctor` check failed |

## init

```bash
px0 init [dir] [--harness claude|gemini|pi|opencode] [--composio-key KEY]
```

Scaffolds a store, asks for a Composio API key, and prints suggested next commands. Safe to run in a script: when stdin is not a terminal it skips the prompt and tells you to set the key later. See [Installation](/get-started/installation).

## workflows

| Command | What it does |
| :--- | :--- |
| `px0 workflows new <description>` | Turn a sentence into a workflow |
| `px0 workflows run [id]` | Run one now; omit the id to pick from a list |
| `px0 workflows edit [id]` | Revise the stored request and rebuild |
| `px0 workflows list` | Every workflow in the store, plus any file that fails to parse |

**`new`** — `--yes` skips every prompt, `--id <id>` names it directly, `--no-clarify` skips the clarifying questions, `--no-discover` restricts it to curated tools. See [Build a workflow](/workflows/build).

**`run`** — `--dry-run` stubs write tools, `--input KEY=VALUE` (repeatable) passes named values, `--stdin` reads piped text, `--output stdout|file` overrides the destination, `--quiet` suppresses decoration, `--json` prints the run record. See [Run a workflow](/workflows/run).

**`edit`** — takes `--yes`, `--no-clarify`, and `--no-discover`.

## tools

| Command | What it does |
| :--- | :--- |
| `px0 tools list [toolkit]` | Every tool a workflow can call, read vs write |

`--status` also asks Composio what is authorized, at one API call per toolkit. `px0 --json tools list` includes each tool's parameter schema. See [Tools](/tools/catalogue).

## knowledge

| Command | What it does |
| :--- | :--- |
| `px0 knowledge add <url-or-file>` | Ingest a URL, or a `.md`, `.txt`, `.rst`, `.pdf`, `.docx`, or `.odt` file |
| `px0 knowledge refresh <path>` | Re-fetch an already-ingested source |
| `px0 knowledge list` | Every knowledge file |
| `px0 knowledge search <query>` | Retrieve matching passages |
| `px0 knowledge ask <question>` | Answer a question from the library |
| `px0 knowledge reindex` | Rebuild the retrieval index |

**`add`** — `--to docs|blogs|papers` overrides the destination folder, `--no-propose` skips the guideline proposal pass.

**`search`** / **`ask`** — `--k N` sets how many passages to retrieve. `ask` takes `--sources` to print citations. See [The knowledge library](/knowledge/library).

## guidelines

| Command | What it does |
| :--- | :--- |
| `px0 guidelines list` | Every guideline file |
| `px0 guidelines review` | Accept, edit, or dismiss pending proposals |
| `px0 guidelines consolidate` | Wider sweep: proposals, decay, contradictions, unreferenced files |
| `px0 guidelines log <claim-id>` | One claim's edit history |
| `px0 guidelines revert <claim-id> --to vN` | Restore one claim to an earlier version |
| `px0 guidelines why <claim-id>` | How a claim came to say what it says |
| `px0 guidelines alias list` | Claim-id aliases |
| `px0 guidelines alias link <old> <new>` | Link two ids for the same idea |
| `px0 guidelines alias unlink <old>` | Remove an alias |

`review` and `consolidate` both take `--list-only` to print without prompting. A claim id is `<path>#<heading-slug>`. See [Guidelines](/guidelines/overview).

## runs

| Command | What it does |
| :--- | :--- |
| `px0 runs` | Interactive browser over past runs |
| `px0 runs list` | The same rows as plain text |
| `px0 runs show <run-id>` | The full JSON record |
| `px0 runs output <run-id>` | Just the output |
| `px0 runs logs <run-id>` | The raw log; `--follow` to tail |
| `px0 runs rerun <run-id>` | Run that workflow again; a dry run reruns as a dry run |
| `px0 runs why <run-id>` | How the run reached its result |

`list` takes `--workflow <id>`, `--failed`, `--since <age>` (`12h`, `7d`, `2w`), and `--json`. `px0 runs` with no terminal falls back to the plain listing, and only the current store's runs are listed. See [Browse runs](/runs/browse).

## daemon

| Command | What it does |
| :--- | :--- |
| `px0 daemon install` | Install the scheduler for your OS |
| `px0 daemon status` | Alive or not, last fires, next fires |
| `px0 daemon start` / `stop` / `restart` | Control it |
| `px0 daemon serve` | Run it in the foreground |
| `px0 daemon logs` | The daemon log; `--follow` to tail |

`install` takes `--fallback-cron` to force cron over the native mechanism. See [Schedules and the daemon](/workflows/schedule).

## versions

| Command | What it does |
| :--- | :--- |
| `px0 versions list <path>` | Every version of a file |
| `px0 versions show <path>@vN` | One version's contents |
| `px0 versions diff <path> <v1> <v2>` | Diff two versions |
| `px0 versions revert <path> --to N` | Restore a file to a version |
| `px0 versions prune` | Apply the version cap; `--dry-run` to preview |

Paths are relative to the store, e.g. `workflows/friday-pr-digest.md`. See [Provenance and history](/guidelines/provenance).

## changes

| Command | What it does |
| :--- | :--- |
| `px0 changes list` | Every recorded change, newest first |
| `px0 changes show <change-id>` | One change's files |
| `px0 changes revert <change-id>` | Undo one change across all its files |

`list` takes `--since <age>` (`12h`, `7d`, `2w`), `--actor <name>`, and `--json`.

## skills

| Command | What it does |
| :--- | :--- |
| `px0 skills build` | Compile `guidelines/` into agent skill bundles |
| `px0 skills <anything else>` | Forwarded to `npx skills <args> -g` |

Common forwarded verbs are `search`, `add`, `list`, `check`, `update`, and `remove`. See [Agent skills](/skills/agent-skills).

## store

| Command | What it does |
| :--- | :--- |
| `px0 store list` | Workflows, guidelines, and knowledge in one pass |
| `px0 store export <dir>` | Portable copy of content and history, secrets stripped |

`export` copies content and history with secrets stripped: the Composio key is blanked in the exported `config.toml` and purged from its version history. See [The store](/reference/store).

## config

| Command | What it does |
| :--- | :--- |
| `px0 config list` | Every key with its value, default, and description |
| `px0 config get <key>` | One key's current value |
| `px0 config set <key> <value>` | Validate and save one key |
| `px0 config model` | Pick a harness and model interactively, verifying it works |
| `px0 config composio [key]` | Set the Composio API key; prompts and masks if omitted |

See [Configuration](/reference/configuration).

## doctor

```bash
px0 doctor [--quick] [--json]
```

Runs every health check and prints a concrete fix for each failure. Exits `0` when all pass, `4` when any fail. `--quick` skips the slower checks — daemon, harness, index — that need a live subprocess or a filesystem walk.

The checks are `credentials`, `versions`, `locks`, `schema`, `connections`, `workflows`, `unreferenced_guidelines`, `update`, `daemon`, `harness`, and `index`. See [Troubleshooting](/reference/troubleshooting).

## update and version

```bash
px0 version
px0 update [--check] [--channel stable|beta]
px0 update rollback
```

See [Updating px0](/reference/updating).

## Environment variables

| Variable | Effect |
| :--- | :--- |
| `PX0_HOME` | Store location. Defaults to `~/.px0`. |
| `COMPOSIO_API_KEY` | Read at startup if the stored key is absent |
| `SSL_CERT_FILE` | CA bundle for connector TLS; always wins over `connectors.ca_bundle` |
| `NO_COLOR` | Plain output |
| `FORCE_COLOR` | Keep colour through a pipe |
| `PAGER` | Used by the run browser's log view |
